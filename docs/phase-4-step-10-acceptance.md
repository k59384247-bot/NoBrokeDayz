## Combined local acceptance

`npm run check:phase4` pins Node/npm/Deno/Supabase versions, confirms all current migrations and SQL test files, then runs the case handlers, audit checkpoint, Phase 1/2 regressions/toolchain/type/lint/format checks, marketplace boundary tests, payment tests and local Edge journey sequentially. It reuses the recorded Phase 3 failure/restore evidence instead of mutating migrations. Its terminal `check:database` rebuilds migrations, runs the SQL permission suite, cleans marked synthetic fixtures, compares generated public types and stops local Supabase. The wrapper redacts credentials and records per-step durations and a safe source manifest. Failure remains failure even when cleanup succeeds.

The populated checkpoint is created in `check-marketplace-local.mjs` after the Step 9 synthetic refund trace and before any reset. The private Ed25519 key remains in process memory; the trusted public key and retained checkpoint live under an OS temporary directory outside the repository/database. A later reconciliation audit event must advance the live chain while the earlier signed anchor still verifies.

This local suite does not establish production provider compatibility, bank receipt, independent production signer custody or separately controlled checkpoint storage. Those remain launch requirements.
